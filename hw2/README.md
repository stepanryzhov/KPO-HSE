# ПОС — преподавательская оценка студентов

Консольное приложение на Go: студенты, критерии оценивания, выставление,
исправление и отмена оценок, расчёт итогов и экспорт ведомости в CSV.

## Запуск

Нужны Go 1.22 или новее и `make`. Команды выполняются из корня проекта:

```bash
make run   # обычная работа
make demo  # готовая демонстрационная ведомость
make test  # запуск тестов
```

Основной сценарий в меню: **1** — добавить студентов, **3** — зачислить их
в ведомость, **5** — создать критерии, **7** — выставить оценки,
**10/11** — посмотреть итог студента или всю ведомость, **12** — экспортировать CSV.
Пункт **13** позволяет выбрать или создать другую ведомость.

Демо запускается на временной копии данных; пункт **11** показывает готовую таблицу.
Пошаговый сквозной сценарий описан в [DEMO.md](DEMO.md).

## Доменная модель (DDD)

Термины предметной области используются в названиях типов и операций:

| Понятие | Тип | Роль |
|---|---|---|
| Студент | `Student` | Entity с ID в общем реестре |
| Критерий | `Criterion` | Entity с ID внутри ведомости, максимумом и весом |
| Оценка | `Evaluation` | Entity с составным ключом: студент и критерий |
| ID, имя, балл, вес | `id`, `name`, `score`, `weight` | Value Objects с проверками при создании |

Студенты с одинаковыми именами различаются по ID. Значения `score` с одинаковым
баллом равны по значению и не имеют собственной идентичности.

Границы агрегатов:

- `StudentRegistry` хранит общий реестр и выдаёт ID студентов.
- `Gradebook` объединяет состав ведомости, рубрикатор и оценки; через него
  выполняются изменения оценок. `CriterionRegistry` входит в этот агрегат
  и выдаёт локальные ID критериев.

Инварианты охраняет доменная модель:

- оценка допустима только для студента и критерия текущей ведомости;
- `0 <= score <= max_score`, максимум и вес строго положительны;
- числовые значения конечны, имена непустые;
- на пару студент/критерий приходится одна оценка: повторное выставление
  заменяет её, отмена удаляет.

Domain Service — функции `CalculateFinalMark` и `CalculateAllFinalMarks`.
Итог рассчитывается по текущим оценкам как `Σ(score × weight)`; веса
не нормализуются. Для расчёта нужны критерии и оценки по каждому из них.

## Архитектура и DI

Используется упрощённая Clean Architecture. Правила оценивания находятся
в домене, сценарии — в сервисах приложения, ввод/вывод — в адаптерах.

| Слой | Расположение | Ответственность |
|---|---|---|
| Domain | `internal/core/domain` | Сущности, VO, агрегаты, инварианты и расчёт итогов |
| Application | `internal/features/students/service`, `internal/features/gradebooks/service` | Сценарии, порты репозиториев, подготовка отчёта |
| Adapters | `internal/features/*/repository`, `internal/features/export`, `cmd/app/cli.go` | JSON, DTO, CSV и консоль |
| Composition root | `cmd/app/container.go` | Сборка зависимостей |

Направление зависимостей: `CLI → Application → Domain`,
`Adapters → Application/Domain`. Домен использует только стандартную библиотеку.

Порты `Repository` объявлены в сервисах; JSON-репозитории реализуют сохранение.
Загрузка и преобразование DTO выполняются в адаптерах через доменные методы.
Ручной DI-контейнер `Container` создаёт репозитории, загружает данные и передаёт
зависимости в конструкторы сервисов. Оба сервиса используют общий реестр студентов.

## Паттерны GoF

| Группа | Паттерн и место | Какую задачу решает |
|---|---|---|
| Порождающий | Фабричное создание доменных объектов — `NewEvaluation`, `StudentRegistry.CreateNewStudent`, `CriterionRegistry.CreateNewCriterion` | Централизует создание объектов и проверку инвариантов; реестры также выдают ID. |
| Структурный | Facade — сервисы студентов и ведомости | Объединяет доменные операции и сохранение за понятными методами для консоли. |
| Поведенческий | Command — `command` и список команд в `CLI.Run` | Хранит название и обработчик действия вместе; общий цикл меню выполняет выбранную команду через `func() error`. |

## Данные и тесты

Успешные изменения сохраняются в JSON: студенты — в `data/students.json`,
ведомости — в `data/gradebooks/`. При запуске открывается `default`.
JSON подходит для локального приложения и позволяет сохранять состояние без БД.
При ошибке сохранения программа завершается, чтобы не продолжать работу
с несохранёнными изменениями. Экспорт принимает расширение `.csv`
без учёта регистра и запрашивает подтверждение перезаписи существующего файла.

Оставлены четыре unit-теста домена: границы балла, неизвестный критерий,
расчёт итога, исправление и отмена оценки. Один сквозной тест проверяет
консольный сценарий, CSV и восстановление данных после повторного запуска.

## Использование ИИ

ИИ помог с ревью кода и сверкой с ТЗ, проверкой сценариев, исправлением
валидации пути CSV, подготовкой тестов и README. Изменения проверялись
сборкой, тестами и сквозным сценарием работы приложения.
